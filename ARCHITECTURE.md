# PhotoKontur — архитектура нового сайта

Решение принято до реализации, 01.10.2026. Режим build. Старый output/prototype — только содержательный референс; его код, зависимости и CSS не используются.

## Сравнение

| Кандидат | Польза для задачи | Ограничение | Решение |
|---|---|---|---|
| Astro | Статические HTML для каждого URL, файловые маршруты, шаблоны и контент, локальный JS только для интерактивности | Серверная форма потребует отдельного API | Выбран |
| Next.js App Router | Маршруты, серверные компоненты, развитые CMS-интеграции | React и серверные возможности избыточны для этого релиза | Не установлен |
| Vite + React | Удобен для сложного приложения и тура | Для статей потребуются маршрутизация и пререндер отдельно | Не установлен |
| Driver.js | Подсветка, backdrop, стрелка, клавиатура; работает без React | Состояние симуляции нужно реализовать самостоятельно | Выбран, MIT |
| Shepherd | Развитые шаги и управление турами | Больше возможностей, чем нужно; коммерческие условия требуют отдельной проверки перед внедрением | Не установлен |
| CSS transitions/keyframes | Без дополнительного JS, reduced-motion через media query | Нет сложных таймлайнов | Выбраны для наведения и небольших вступительных движений |
| Motion | Web Animations, подходит для независимых интерактивных элементов, MIT | Дополнительная зависимость без необходимости | Не установлен |
| GSAP | Сложные таймлайны и ScrollTrigger | Для этого сайта избыточен; собственная лицензия GSAP | Не установлен |
| Lucide Astro | SVG на этапе сборки, единый набор, ISC | Не нужен клиентский runtime | Выбран |
| Radix UI | Доступные сложные React-примитивы, MIT | Потребует React ради простых disclosure/menu | Не установлен; используем native details и кнопки |

## Выбранные версии

Node 24.19.0; pnpm 11.25.0; Astro 7.3.5 (MIT); driver.js 1.8.0 (MIT); @lucide/astro 1.49.0 (ISC); @fontsource-variable/manrope 5.3.0 (OFL-1.1). Прямые зависимости фиксируются без диапазонов, транзитивные — в pnpm-lock.yaml. Никаких CDN в runtime.

## Структура

```text
src/
  layouts/BaseLayout.astro       — метаданные, шапка, подвал
  components/                   — CTA, продуктовые кадры, кейс, статьи, тур
  content/articles.ts           — типизированные редакционные материалы
  components/LiveDemo.astro      — оболочка изолированного кабинета
  styles/                       — tokens, global, home, tour
  pages/                        — файловые маршруты
public/media/                   — полные исходные скриншоты и атмосферные фото
public/demo/app/                — 18 адаптированных статических экранов
public/demo/bridge.js/css        — восьмишаговая экскурсия и безопасный протокол
qa/                             — браузерные снимки
ARCHITECTURE.md, CONTENT_REQUIRED.md, ASSETS.md, qa-report.md
```

Маршруты: `/`, `/benefits/`, `/how-it-works/`, `/blog/`, `/blog/[slug]/`, `/cases/`, `/cases/studio-workflow/`, `/faq/`, `/apply/`, `/privacy/`, `/consent/`, `/cookies/`, `/404.html`. Каждая страница открывается напрямую. Выход сборки — dist/, нужен HTTP-сервер, не file://.

Контент статьи: slug, title, category, excerpt, cover, preparedAt, sections. Содержание отделено от шаблонов, CMS впоследствии возвращает ту же модель. Даты обозначают подготовку редакционного материала, а не существующую историю публикаций. Кейсы пока только явно обозначенные редакционные сценарии.

CSS: фирменные токены из локального сервиса, общие layout-примитивы, отдельный stylesheet главной и тура, scoped styles компонентов. Manrope локальный, маркетинговая шкала заголовков. Мобильный breakpoint 760px, планшет 1100px. Без глобального скрытия overflow для маскировки дефектов.

## Тур и доказательства

Сквозной сценарий текущей итерации: съёмка → альбом → персональная папка → клиентский предпросмотр → выбранные кадры → состав демо-заказа → дашборд. Источник — статические экраны локального fotokontur-site. Экскурсия подсвечивает реальные элементы; кабинет доступен без экскурсии. Реальные снимки интерфейса используются отдельно в рекламных блоках, всегда целиком. Демо не выполняет оплату или серверное сохранение; цифры явно демонстрационные.

## Итерация по брифу · 01.10.2026

Стек не менялся. Существующие Astro маршруты, layout и компоненты сохранены. Добавлены VisionFeature, CommercialSections (смысловые секции), TestimonialDraft и LiveDemo. Главная собрана из прежних и новых компонентов. Устаревшие GuidedTour/tour.ts/tour.css удалены после замены.

LiveDemo встраивает /demo/app/*.html с sandbox="allow-scripts". Нет allow-same-origin, forms, popups, top-navigation или downloads. CSP запрещает connect-src, form-action, object-src; нет обращений к рабочим API. Экскурсия Driver запускается внутри iframe и подсвечивает настоящие DOM-элементы. Переходы тура передают только индекс 0–7 в query. Данные формы/фото между parent и iframe не передаются.

Ограниченный протокол postMessage: parent проверяет event.source === iframe.contentWindow, origin === null, channel, enum события, allowlist экрана и индекс. Child проверяет source === parent и origin равный origin URL самого демо. Команда parent→child только exit; для доставки непрозрачному origin используется '*', без данных пользователя. Child→parent идёт на конкретный origin. Внешние ссылки и отправка форм блокируются; демонстрационные изменения живут только в памяти текущего экрана.

Свободное исследование: навигация референса + селектор разделов, reset, разворачивание. Тур: старт/повтор, восемь шагов, назад/далее, реальные клики, Escape, пропуск, финальный CTA. Экран заказа добавлен к клиентскому предпросмотру, чтобы показывать фактически выбранные кадры, а не ложное уведомление об оплате. Встроенные данные не являются backend-тестом.
