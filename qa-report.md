## Главная и контент

- Порядок: hero → интерактивное раскрытие инструментов → VK Vision/персональные папки → дашборд → сокращение рутины → экономика/комиссия → пошаговый процесс → планирование → родительский кабинет → подключение → безопасность → кейсы/отзыв → эквайринг → материалы блога → контакт → заявка.
- Концептуальный визуал VK Vision не обещает действующую интеграцию: найденный код моделирует распознавание на fixtures, подтверждённого API нет. Этот статус виден рядом с визуалом.
- Числовые выгоды, проценты комиссии, имя клиента или цитата не выдуманы. Отзыв представлен честным компонентом, реальные материалы обязательны перед публикацией.
- Эквайринг имеет отдельный резервный блок с перечислением будущих условий и явной пометкой.
- Отдельные страницы сохранены. Регистрация вторична. Большой повторный CTA убран из FAQ, блога и статей; на «Как это работает» убрана ссылка на саму страницу в финальном CTA.

## Демо и экскурсия

- Изучены /demo-функция референса в src/views/pages.js и фактические кликабельные public/demo/app. Для браузерного изучения использовалась read-only статическая оболочка, а не сервер Express референса.
- Перенесены 18 статических экранов; сервер, admin routes, env и базы не копировались.
- Восемь шагов пройдены на desktop и mobile: съёмка → альбом → папка → предпросмотр → кадр → оформление → состав → дашборд.
- На desktop проверены клики по самим выделенным элементам. На mobile — все шаги «Далее» и обратный ход. Проверены повтор, пропуск, Escape и внешняя кнопка выхода. Фокус после выхода возвращается к старту.
- Подсветка, затемнение, стрелка Driver и подсказка находятся внутри iframe, привязаны к настоящему элементу.
- Без тура проверен путь: открыть «Осенний бал» → альбом → клиентский предпросмотр → выбрать кадры 2 и 4 → оформить. В составе появились **Кадр 2 · Кадр 4**, без оплаты и серверной отправки.
- Селектор разделов, мобильное меню референса, reset и разворачивание доступны. Разворачивание проверено (aria-pressed=true); данные не переносятся между экранами — это явно указано.
- Все 18 экранов открыты дополнительно на ширине 340 px для проверки узкого iframe. После исправлений пяти проблемных экранов горизонтальное переполнение устранено.
- Изоляция проверена в HTML/коде: sandbox=allow-scripts, без same-origin/forms/popups/top-navigation/downloads; CSP connect-src none, form-action none, object-src none. Child не может читать родительский DOM или рабочую сессию. postMessage ограничен источником, origin, перечислением сообщений/экранов и номером шага. Сообщения не содержат введённые данные.
- Console errors в проверенных сценариях отсутствуют. Это проверка UI-демо, не аудит безопасности production.

## Найденные и исправленные дефекты

1. Старые кропы интерфейса и cover в статьях → полные исходники, natural ratio, открытие крупно.
2. Родительский индикатор тура замирал при переходе iframe → origin сообщения выводится из проверяемого URL демо, а не пропадающего referrer.
3. Заголовок/кнопки фотосессий выходили за узкую ширину → перенос flex-групп.
4. Переполнение строк альбомов, промо шаблона и финансов → локальные responsive правила; финансовые таблицы преобразуются в карточки.
5. В референсе открытие альбома и оформление давали только toast → рабочая навигация и фактический состав выбора в нашей копии.
6. Статический финансовый экран содержал платформенные проценты и балансы компаний → удалены из публичного демонстрационного пути, условия расчётов не выдуманы.
7. Разные название/дата у экранов основного сценария → «Осенний бал», дата и альбом «Группа Ромашка» согласованы.
8. После удаления старого тура пропали стили вводных шагов → перенесены в scoped стили страницы.
